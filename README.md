# ShopNest — MERN E-commerce App
ShopNest is a full-stack shopping application built with MongoDB, Express, React, and Node.js. It includes a customer storefront, cart and checkout flows, email OTP verification, and an admin dashboard.

## Features
### Customers
- Browse products, search by name, and view product details.
- Register with email OTP verification and sign in with JWT authentication.
- Manage a shopping cart and submit a shipping address at checkout.
- Choose Razorpay online payment or Cash on Delivery.
- View account information and order history.
- Access About, Disclaimer, and Return Policy pages.

### Administrators
- View order, product, user, and total order-value statistics.
- Add, edit, and delete products, with Cloudinary image uploads.
- View orders and update their status.
- List and delete users, and create or promote administrators.

## Local Setup
### 1. Prerequisites
- A current Node.js LTS release and npm compatible with the dependencies.
- A local MongoDB instance or MongoDB Atlas connection string.
- A Gmail account with an app password for verification emails.
- Cloudinary credentials for product image uploads.
- Razorpay test credentials for testing online checkout.

### 2. Install dependencies
From the repository root:

```powershell
npm run install-all
```

### 3. Configure the backend
Create `backend/.env` with your own values:

```dotenv
PORT=5000
NODE_ENV=development
MONGO_URI=mongodb://127.0.0.1:27017/shopnest
JWT_SECRET=replace_with_a_long_random_secret
FRONTEND_URL=http://localhost:3000
GMAIL_USER=your_email@gmail.com
GMAIL_PASS=your_gmail_app_password
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
RAZORPAY_KEY_ID=your_razorpay_test_key_id
RAZORPAY_KEY_SECRET=your_razorpay_test_key_secret
```

Never commit real credentials. `.env` files are ignored by the root `.gitignore`. Gmail credentials are needed for registration verification; Cloudinary and Razorpay credentials are needed for their respective features.

### 4. Start development servers
```powershell
npm run dev
```

- Frontend: http://localhost:3000
- Backend: http://localhost:5000
- Products API: http://localhost:5000/api/products
The frontend proxies `/api` requests to port `5000`. If you change the backend port, update `proxy` in `frontend/package.json` too.

## Sample Data and Admin Access
> **Warning:** `npm run seed` deletes every existing user and product in the configured database before inserting sample data. It does not clear orders. Use only a disposable development database.

```powershell
npm run seed
```

The seed adds four products and an admin account with email `admin@shopnest.com` and password `password123`.

## Payment Configuration Notes
The backend reads Razorpay credentials from `backend/.env`, but `frontend/src/pages/Checkout.jsx` currently uses the placeholder public key `rzp_test_dummykey123`. Replace that checkout key with the matching Razorpay **test key ID** before testing online payment. Never place the Razorpay key secret in frontend code.

Cash on Delivery skips online payment and submits an order with a generated bypass transaction ID. Treat the current payment flow as a development implementation and review it before accepting real payments.

## Available Commands
Run these from the repository root:

| Command | Purpose |
| --- | --- |
| `npm run install-all` | Install root, backend, and frontend dependencies |
| `npm run dev` | Run both development servers |
| `npm run start:backend` | Start the backend with Nodemon |
| `npm run start:frontend` | Start the React development server |
| `npm run build` | Install frontend dependencies and build into `frontend/build` |
| `npm start` | Start the backend with Node.js |
| `npm run seed` | Replace users and products with development seed data |
| `npm --prefix frontend test` | Run the configured React test runner |

The backend has no test script configured. A frontend test command is available, but no application test files are included in the current source tree.

## API Overview
Authenticated endpoints expect `Authorization: Bearer <token>`. Admin endpoints also require the `admin` role.

| Base path | Responsibilities |
| --- | --- |
| `/api/auth` | Registration, login, OTP verification/resend, admin user management |
| `/api/products` | Public product list/details; admin product creation, updates, deletion |
| `/api/orders` | Authenticated order creation/history; admin order list/status updates |
| `/api/payment` | Razorpay order creation and signature verification |
| `/api/analytics` | Admin summary statistics |

## Production Build
The backend serves the compiled frontend when `NODE_ENV=production`.

```powershell
npm run build
$env:NODE_ENV = "production"
npm start
```

Configure production secrets and set `FRONTEND_URL` to your frontend origin. Open the backend host and configured port to access the app. The frontend uses relative `/api` URLs, so a separate frontend deployment needs a reverse proxy or corresponding API URL changes; CORS configuration alone does not redirect requests.

Before public deployment, replace demo credentials, configure real service accounts, and review authentication, input validation, payment handling, and authorization. Build and runtime behavior should be tested in your target environment.
